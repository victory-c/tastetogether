# Manual acceptance guide

This guide maps to PRD section 11. Record the date, environment, observed result, and any failure for each item. A missing control or behavior is a failure, not a pass. Use a valid Qloo key and live service for the end-to-end checks; use controlled test responses for rare data and error states. Do not substitute mock fixtures for the live demo.

1. **Public demo and live Qloo.** Open the deployed site in an incognito window without private approval. Start the sample experience, confirm both people are labeled as samples, and request recommendations. Verify server-side request evidence shows real Qloo calls. If no public deployment exists, record this check as blocked and perform the local part separately.
2. **Solo memory.** In a normal browser, create a profile with at least three resolved positive entities. Add a resolved place as visited, refresh, and verify the entry persists. Request a solo recommendation with visited-place exclusion on; verify that place is absent.
3. **Two independent browsers.** Create a room in the normal browser and copy its invite link. Open the link in a separate incognito window, create or use a different profile, consent, and join. Verify both participants appear and each browser can access only its own full profile and history.
4. **Shared exclusions and constraints.** Add different resolved visited places to each profile, then enable exclusion of places either person visited. Set cuisine exclusions, area and radius, and a price level. Confirm conditions in both browsers and request results. Check neither person's visited place appears and that known cuisine, location, and price constraints are respected. Unknown price must be identified as unverified.
5. **Decision modes.** Request three options and verify at most three are shown. Switch to pick mode and request one; use **Try another** and verify the rejected place does not return in that session. Check that rejection did not create a permanent visited memory.
6. **Honest states.** Use controlled test responses to exercise fewer than three qualifying places, no qualifying places, a candidate with missing hours, and an unresolved history entry. Verify the actual count or no-match state is shown, unknown hours say **Hours unverified**, and unresolved history is flagged as potentially incomplete. For a Qloo timeout, temporarily set `QLOO_API_URL` in `.env.local` to an unreachable host, restart the app, and request recommendations; verify a retryable provider-unavailable state instead of invented results. Restore the URL and restart afterward.
7. **Staleness and ownership.** Generate a room result, then change a constraint and verify the old result is marked stale until a new run. From one browser, attempt to read or modify the other user's profile or memory using a direct API request and the other object's identifier; verify access is denied and the other user's data is unchanged.
8. **Traceable facts.** Compare result names, addresses, and factual claims with the returned Qloo data and recorded inputs. Verify unknown information is labeled, and no wait minutes, exact spending amounts, or other unsupported restaurant facts appear.
9. **Feedback.** Select a recommendation and verify that selection alone does not add a visited memory. After dining, use **We went here**, provide feedback, and verify only the acting user's history gains the visited entry. Repeat independently for the other participant.
10. **Clean setup and incognito access.** From a clean checkout, follow the README setup with a valid key. Verify the local database initializes and the app runs. In an incognito window, check the demo and public repository access once deployed and published; record unavailable deployment or repository access as blocked.
11. **English-only experience.** Repeat solo, two-person, demo, empty, and failure flows in English and Chinese-language browser settings. Enter some Chinese text as user input. Verify all system-generated labels, messages, explanations, and errors remain English while original user input and official place names are preserved.
